# AUTH-12 — Atomic ledger/reservation coordinator

База ad4fd342eeba39161e69cce736d9d5d25f1cea2f, 08.11.2026 (Москва), отдельный detached worktree; AGENTS/spec_auth/spec_auth_architecture §5/7/9 и AUTH-08…11 изучены. AUTH-12 — durable доменный admission coordinator и transactional job intent/outbox. Его trusted interface вызывается после AUTH-11 object/actual-workload gate; подключение реальных worker queues/start/settle/recovery — отдельный AUTH-13. Новые HTTP endpoints и автоматический коммерческий CU launch не вводятся. Текущие scientific handlers сами по себе не объявляются финансово metered: без AUTH-13/14 нельзя заявлять end-to-end billing.

## Решение

PostgreSQL authority в существующем PostgresAccessStore. Новая explicit0025, предыдущие SQL/checksums не меняются. Scope tree sponsor→campaign→account→grant, либо обычный account без sponsor. Родитель/owner/deadline/version immutable, policy changes CAS + mandatory существующий auth_audit_outbox. Account counters сохраняются независимо от cookies/keys/плана. Месяц API — UTC YYYY-MM, analyses — lifetime, без reset при upgrade/downgrade. CU и concurrency требуют явных finite server budgets; никакого NULL monetary infinity. CU — integer micro-CU, сумма и промежуточные выражения в пределах signed BIGINT, float/bool/overflow запрещены. Измеренная стоимость и version поступают только trusted server quote; benchmark/prices AUTH-14/18, source-aware wallet/lots AUTH-21, не второй кошелёк в AuthN.

В одной транзакции: schema/current Identity→Account→membership; сериализация Account; chain scopes/budgets в порядке sponsor/campaign/account/grant, deterministic UUID внутри уровня; текущие caps/versions и functional registry; idempotency; quota checks; reservation/allocations; immutable balanced ledger postings; analysis claim; job intent/outbox и mandatory audit intent. Нет внешнего broker/audit sink внутри SQL. Parent ceilings кумулятивны, все либо ни один. Authority/outbox/audit failure откатывает counters/claim/job/ledger. Lock timeout не разрешение. Два Account одного sponsor конкурируют за общий остаток. Внешние IDs не proof; scope chain задаётся persisted policy, не входным browser списком.

Idempotency account+actor+canonical operation+hash(key), нормализованный digest включает payload/resource/workload/stage/quote/deadline/API-vs-browser. Credential ID не ключ usage. Replay того же запроса возвращает прежний receipt/result reference без нового job/charge; другой payload409. Raw payload/секрет/idempotency key не сохраняется, только digest и безопасные refs. Дубликат admission не означает повторную публикацию в worker queue. Mandatory authority проверяется до replay; revoked/foreign caller не получает receipt.

API quota — принятые programmatic bindings, исключения versioned server policy. Metadata health не scientific admission. Analysis — первый successful admission нового server run_id на upload/demo/DB, claim уникален account/run; processing/restores не создают второй analysis. API/analysis consumed при admission и не возвращаются при ошибке execution. CU/concurrency held до terminal transition. Ledger balanced available→spent/reserved и reserved→spent/available; counters — SQL-trigger проекция append-only postings; прямое изменение spent/reserved запрещено. Обновление проекции O(1), без пересканирования ledger на каждый admission; индекс поддерживает сверку истории. Settle actual<=held, дополнительный расход только explicit extend до работы; превышение402, никакого отрицательного available. Pending cancel освобождает CU/slot, не API/analysis. Running release без подтверждённой worker reconciliation закрыт; timeout lease не refund. CAS start/settle/extend и terminal replay исключают двойной расход; actual worker fencing adapter остаётся AUTH-13.

## TDD и риски

RED contracts→native SQL races→implementation→GREEN. Нужны: последний CU/API/analysis/slot, общий sponsor/campaign, atomic multi-budget failure, same-key concurrent replay/different body409, credential rotation counters, run claim/restore, current expiry/member revoke/downgrade, SQL immutable ledger/reservations, outbox/audit failure rollback, actual>estimate/extension, terminal idempotency, lease expiry no refund, fresh process/restart/readiness/checksum/trigger drift. Минимальные portable unit, native PostgreSQL16/18 CI, strict INDEX overlay, route map and builds. Legacy scientific regression и commercial certification не объявляются зелёными без доказательства.

Риски: lock inversion с Identity/Account lifecycle; Account serialize before hierarchy shared scopes; monthly boundary clock берётся после lock; нельзя изменять chain или добавлять budgets между reserve/settle без snapshot allocations; no automatic credit/reset; running unknown outcome удерживает reserve; immutable history/overflow; секреты в JSON/audit; auto-migration запрещена. PostgreSQL row locks и READ COMMITTED: https://www.postgresql.org/docs/17/explicit-locking.html и https://www.postgresql.org/docs/17/transaction-iso.html.

Исторический usage до включения координатора не изобретается и не импортируется автоматически. Rollover API открывает новый UTC bucket, прошлые postings сохраняются; analysis claims lifetime. Production financial launch и перенос старого usage требуют согласованного AUTH-13/14/20 rollout, без обнуления действующих ledger buckets.
