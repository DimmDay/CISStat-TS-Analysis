## Решение и риски

Modeling jobs — persisted stepped plans, не отдельная очередь процессов. Render jobs — существующая очередь document_jobs; delivery — только layer1 projection immutable facts. В protected required/scoped профиле вводятся durable worker tickets/delegation, opaque service credential с kinds modeling/render/delivery, FK к AUTH-12 reservation для вычислительных jobs, monotonically increasing fence и bounded attempt/lease/deadline. Cookie не credential worker: хранится только исходный auth reference, worker предъявляет собственный key; актуальные Identity/membership/Account/credential/caps/object/context проверяются до claim, при heartbeat и непосредственно в publication transaction. ENV/legacy/surrogate не обходят protected gate. Legacy dev unbound fixtures остаются отдельным advisory profile.

Admission и существующая запись job/session сохраняются вместе с reservation/job outbox/audit через общий PostgreSQL transaction binding. На publish существующие session/document registries используют ту же транзакцию: current authority + execution fence + CAS/result projection + AUTH-12 settle + mandatory audit commit/rollback вместе. Object store может оставить orphan bytes при abort, но metadata/ref не публикуются. Side effects не повторяются по replay; expired lease не делает старый процесс безопасным. Managed reservations закрыты для обхода через старые AUTH-12 start/settle/release entry points.

Modeling обе stepped aliases получают один guard/process runner и guarded session publication. Render P0/heavy/print допускается по сохранённой делегации; lease reclaim больше не запускает второй живой рендер. Pure work исполняется child process с hard wall bound, portable spawn, stop/join proof; raw credentials/DB handles не передаются. Parent death protection/Linux process group применяется где доступна; неизвестный process/remote renderer outcome остаётся uncertain с удержанием CU/slot. У remote print успешный ответ подтверждает завершение запроса; timeout не считается доказательством остановки удалённого renderer. Reconciler fencing запрещает stale complete, не refund по таймеру. Trusted operator видит uncertain; никакого force-release по одному job ID.

Delivery — service maintenance, не новый analysis/CU: current Account/run/session/context boundary, service identity и атомарные mirror+ack. Не синтезировать личность автора run для системной проекции. Foreign/new run pointer или revoked/expired Account не получает чужие events; committed provenance не переписывается. Исторические unbound queued jobs не auto-claim; их закрытие/повторный authorized admission выполняется оператором после drain прежнего бинарника.

До AUTH-14 финансовый CU launch закрыт. Рабочий server quote counters-only/unpriced-auth13, actual0; integer CU/estimate/version интерфейс AUTH-12 сохраняется для измеренных коэффициентов. Technical concurrency finite (server setting, default1), существующие hard work policies используются без выдуманного прайса. Slots и существующие AUTH-12 counters не reset при ключах/retries; delivery не считается новым analysis. Новая explicit0026, старые SQL/checksums не менять. Для VM нужен api image + migration + provision service credential; web/HTTP methods сохраняются: actual ASGI239 == AUTH-00 API239, новых/удалённых маршрутов нет.
