# Task DKT-2R (2026-09-18) — Калибровка индиго-заголовков: «цвет логотипа» в тёмной теме

**Спецификация:** `spec_dark_theme.md` §10 (фиксация решений тимлида
2026-09-18). **База:** `main` @ `e99cd1f` (DKT-1 + DKT-2). **Автор:**
Claude (Senior dev), платформа CISStat TS Analysis.

---

## 1. Требование тимлида и его калибровка

Требование: «все Заголовки и Подзаголовки цвета индиго должны быть в
тёмной теме такого же цвета, как цвет логотипа — CISStat TS Analysis».

Literal-исполнение (#2E3192 как цвет текста на тёмной поверхности)
невозможно без регресса доступности: **#2E3192 ↔ #16171C = 1.68:1**
(факт пиксельного аудита логотипа DKT-2, `task_dkt2_logo_audit.json`) —
ниже любого порога WCAG 2.1 AA. Поэтому «цвет логотипа» в тёмной
калибровке = **токен `brand-bright` #8F94F5** (hue 237° — точно hue
индиго логотипа; ≥ 4.5:1 на всех тёмных поверхностях) — тот же механизм,
что уже принят для `text-brand` (отчёт DKT-2 §3, 159 инстансов).
Единство цвета всех индиго-заголовков достигается сведением их всех на
один токен.

## 2. Инвентарь (программный скан произвольных hex-классов)

Скан всех .tsx/.ts платформы (packages/ui + обе оболочки, без тестов) на
произвольные цветовые классы `{-}-[#hex]` (text/bg/border/fill/stroke/
from/to/via/ring): **единственный случай — `text-[#1e3a8a]`, 9 инстансов
в 4 файлах** — hero-заголовки (h1/h2) и подзаголовки (p):

| Файл | Инстансы | Элементы |
|---|---|---|
| `HomeHero.tsx` | 2 | h1 (заголовок) + p (подзаголовок) |
| `NavigatorHero.tsx` | 4 | h1 + p + h2 «applied-tasks-title» + h2 «research-stages-title» |
| `TasksHub.tsx` | 2 | h1 + p |
| `PlatformIntroduction.tsx` | 1 | h2 «platform-navigation-title» |

`text-[#1e3a8a]` — вне канона каталога §6.1 (произвольное значение,
скан оракула DKT-2 ловил только канонические bg-*/text-*), в тёмной теме
оставался #1E3A8A ≈ **1.7:1** на странице #0B0C10 — FAIL. Проверка
смежных случаев: `text-blue-900` (4 инстанса, Modeling/TsAnalysisModeling)
— мелкие 10px-лейблы на `bg-blue-50` (не заголовки), каталог уже ревизовал
(#DBEAFE на #131C2B) — вне компетенции DKT-2R.

## 3. Решение (механизм §6.2, ноль правок в компонентах)

Utility-ревизия в `packages/ui/globals.css`:

```css
.dark .text-\[\#1e3a8a\] { color: rgb(var(--c-brand-bright)); }
```

Светлая тема — байт-инвариант (правило существует только в области
`.dark`; светлые пиксели не меняются). Компоненты не правятся (аргумент
«ноль правок» §3.3). Контроль-инвентарь встроен в тест: появление любого
нового произвольного цветового класса без тёмной ревизии валит сюиту.

## 4. Верификация (TDD RED→GREEN)

- Новая сюита `packages/ui/heading-indigo-calibration.test.ts` — 7 тестов:
  инвентарь (все произвольные классы имеют тёмную ревизию; пин 9/4),
  ревизия → brand-bright, AA 4.5:1 против страницы #0B0C10 и карточки
  #16171C, hue-идентичность логотипу (допуск ±2° на квантование каналов),
  светлая инвариантность (нет нескопированного правила; светлый
  brand-bright == #2E3192). RED: 3 падения → после ревизии GREEN 7/7.
- CSS-бандл-смоук (`scripts/task_dkt2/css_bundle_smoke.mjs`) — PASS
  (селектор с экранированием компилируется).
- Полная регрессия и typecheck/build — см. worklog7.md среза.
