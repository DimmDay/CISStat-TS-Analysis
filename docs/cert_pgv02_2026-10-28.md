## 7. Находки

**F-P2C1 (высокая/средняя; пины b01/b02): `ensure_print_document_revision` не проверяет существование и run-принадлежность basis-артефактов.** Ревизия создаётся с `basis_artifact_ids=["art-ffff…"]`, отсутствующими в реестре (пины ставятся на несуществующие объекты), и с артефактом ЧУЖОГО run (пин на чужой объект в своём run). Нарушение §10.2 «revision с frozen refs/pins» (refs обязаны быть допустимыми) и духа §5/§11 object authorization (артефакт другого run не является допустимым basis). Динамические пробы — `protocols/probe_findings.txt` (F1/F1b).

**F-P2C2 (средняя; пин b03): CAS freeze fail-open на нечисловой строке ревизии.** `freeze_visual_print_snapshot` парсит `expected_context.data_revision` (`str.strip().isdigit()`); схемой PGV-01 строка допускается любая непустая (`_str`), поэтому `data_revision="abc"` проходит валидацию, но молча пропускает сверку ревизии: снапшот декларирует `refs.data_revision="42"`, фактическая ревизия запуска 7 — freeze ПРОШЁЛ (артефакт зарегистрирован). Нарушение PGV-AC07-духа («смена данных при freeze → 409 или явный historical ref, не смешанный print»): тихий пропуск вместо 409 или честного unknown.

**F-P2C3 (низкая; пин b04): `manifest_artifact_id` вне basis_fingerprint.** Fingerprint тела — `{print_kind, basis_kind, basis_artifact_ids, snapshot_id, profile_id}`; повтор с тем же basis, но другим manifest молча возвращает прежнюю ревизию с чужим manifest (аргумент принят и отброшен). Аналог класса F-D7C1/F-D8C1 (контракт↔код).

**F-P2C4 (низкая; пин b05): самоссылка `previous_snapshot_ref == snapshot_ref` принимается** валидатором чекпоинта — история «предыдущий снимок = сам снимок» не имеет смысла (§8) и не отвергается.

**F-P2C5 (низкая; пин b06): частичное состояние при отказе пина.** В `freeze_visual_print_snapshot` артефакт регистрируется persist'ом ДО постановки пина зависимости; отказ `pin_ref` (сломанный storage) поднимает исключение при уже зарегистрированном артефакте — операция вернула отказ, а durable-факт остался (без пина зависимости; повтор с тем же payload вернёт existing и пин доставит — eventual consistency, но первая попытка нарушила AC08-дух «либо валидный результат, либо явный отказ без частичного состояния»).

**F-P2C6 (низкая; класс F-D2C1; пин b07): Memory-реестр печатных ревизий не обеспечивает UNIQUE-ограничения DDL.** `UNIQUE(document_id, version_no)` и `UNIQUE(document_id, basis_fingerprint)` из 0016 в Memory отсутствуют — дубликаты принимаются молча (Postgres отклонил бы). Сервисный поток маскирует класс проверкой check-then-create, но контракт реестра (структурный паритет — урок F-D2C1) неполон; тот же класс несёт и легаси `register_revision` (предсуществующий паттерн — замечание к серии, не регресс поставки).

**F-P2C7 (средняя; пин b09; дельта-0): необновлённые пины счётчиков миграций doclog3/doclog7/doclog9** — заявленный критерий «пины счётчиков обновлены честно» выполнен на 4 из 7 пин-файлов; полный tests/api даёт 3 новых отказа против родителя (см. §5). Фикс — правка трёх пинов (16/96 + последний файл 0016 в doclog9), прецедент «честного обновления пина» DOCLOG-9.

**Наблюдения (неблокирующие):**
- **N-P2C1** (пин b08): `context.data_revision` чекпоинта проверяется только на `is None` — пустая строка принимается как «обязательная ревизия» без значения (класс F-D7C2).
- **N-P2C2**: идемпотентность печатных документов — check-then-create без атомарности (гонка двух `ensure` с разными basis → одинаковый version_no; в PG — IntegrityError на UNIQUE → 500 вместо 409; `register_document` — `ON CONFLICT (document_id) DO NOTHING` при `UNIQUE(run_id, kind_code)`). Аналог N-D8C3; для Memory-пилота — принято.
- **N-P2C3**: `PostgresDocumentRegistry._print_revision_from_row` фабкует `created_at=_now_iso()` при NULL (честнее — None/причина; класс AC12).
- **N-P2C4**: `print_methods_in_abc` пуст — печатные методы ABC реализованы паттерном «NotImplementedError-тело» без @abstractmethod (инстанцируемость ABC сохраняется; паритет классов проверен hasattr-оракулом a31).
