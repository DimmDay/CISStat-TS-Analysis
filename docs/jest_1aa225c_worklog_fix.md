# JEST-1AA225C-FIX — повторное падение B1 в GitHub Actions

Дата: 30.10.2026. База: `main@1aa225ce22d162d837711e5e3d72bbe51817278e`.
Синхронизация выполнена по указанию тимлида, в отдельном detached worktree;
предыдущие локальные изменения сохранены. Правила `AGENTS.md` прочитаны.

## Подтверждённая причина

В run [41015019014](https://github.com/DimmDay/CISStat-TS-Analysis/actions/runs/41015019014)
на [Ubuntu](https://github.com/DimmDay/CISStat-TS-Analysis/actions/runs/41015019014/job/123929278652)
и [Windows](https://github.com/DimmDay/CISStat-TS-Analysis/actions/runs/41015019014/job/123929278327)
падает один и тот же B1 в `scripts/pgv07cert/test_p7cert_findings.test.tsx`:
**Expected 62, Received 41**. Обе приложенные выгрузки `jest-results.json`
подтверждают **237 suites / 2740 tests: 1 failed, 2739 passed**, runtime errors=0.
Логи получены через GitHub-плагин, JSON-артефакты прочитаны из вложений.

В обоих jobs установка, сборка renderer и typecheck обеих оболочек завершились
успешно. Ошибка exit code 1 относится к шагу Jest. Предыдущие проблемы Actions
runtime, shell/Python/Playwright и Upload в этих двух отчётах не воспроизвелись.

Исходный абзац `### Верификация` в разделе `## Task ID: PGV-07 (2026-10-29)`
на строке 962 всё ещё содержит:

```text
Doc-contract гвард scripts/pgv07/check_documents.py — 62/62.
```

Поздняя запись в конце журнала сообщает об исправлении, но B1 читает исходное
заявление PGV-07. Добавление новой записи не изменяет первое заявление.

Сверены все **35 файлов** предыдущей поставки `cisstat-jest-b613120-fix.zip`
с коммитом `1aa225c` (нормализация только CRLF→LF). Единственное различие —
эта строка журнала: в поставленном ZIP было **41/41**, в GitHub осталось
**62/62**. Замена только этого первого заявления делает журналы полностью
одинаковыми. Доказательство: `protocols/delivery-audit.json`.
Это подтверждает конкретное отсутствующее изменение; способ переноса файлов
на GitHub по имеющимся данным не устанавливается.

## Решение и процесс

1. Проверены текущий SHA, структура, AGENTS.md, оба CI job и оба вложения.
2. После чистого `npm ci` воспроизведён существующий B1 RED (1 failed / 4 passed).
3. Создан отдельный `scripts/jest-1aa225c/pgv07-count.patch` с одной заменой
   в исходном разделе PGV-07. Проверены `git apply --check`, само применение
   и `git apply --reverse --check`; все exit=0, изменена ровно одна строка.
4. Исправленный полный журнал также включён в ZIP; добавлена новая запись
   задачи в конец журнала. Оба изменения требуются при ручном переносе.
5. Проверен полный Jest, сборка renderer и typecheck. Упаковка проверяет точный
   состав, CRC и байты файлов; контрольная распаковка дополнительно применяет
   отдельный patch к оригинальному журналу и сверяет результат.

Продуктовые файлы, тест B1, Python-гвард, зависимости и workflow не менялись.
Новый тестовый код для этой документной замены не требуется: существующий B1
воспроизводит дефект и исполняет настоящий гвард. Пропуски и ослабление
assertions не добавлялись. Исторические упоминания 62/62 в актах сертификации
и описаниях прежних дефектов оставлены как история; глобальной замены нет.

Риски: при переносе только новой записи журнала исходная строка останется
неверной и B1 снова упадёт. Полный файл и отдельный однострочный patch дают
два проверяемых способа переноса. Patch намеренно не запускается из Jest/CI:
проверка не должна исправлять собственный входной документ.

## Применение

Основной способ — распаковать ZIP поверх `1aa225c`, полностью заменив
`worklog/worklog11.md`. Отдельный patch при этом применять не требуется.

Если журнал переносится вручную, применить однострочный patch к исходному
журналу **до добавления новой записи**:

```sh
git apply --check scripts/jest-1aa225c/pgv07-count.patch
git apply scripts/jest-1aa225c/pgv07-count.patch
```

Затем проверить именно исходное заявление существующим тестом:

```sh
npx jest --runInBand --runTestsByPath scripts/pgv07cert/test_p7cert_findings.test.tsx
```

Ожидается **5/5**. Полная проверка: `npm run test:ci`.
При уже исправленном журнале повторное применение patch не нужно.
Commit/push не выполнялись согласно AGENTS.md; исправленный GitHub job
может подтвердить только следующий прогон после переноса фактической замены.
