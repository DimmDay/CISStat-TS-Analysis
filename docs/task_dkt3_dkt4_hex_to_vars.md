## DKT-3 — графики, волновые фоны, флоучарты, PNG-экспорт

### 1. Инвентаризация и переменные

Программный скан всех цитированных hex-литералов в `packages/ui/components`

в 36 файлах. Карта ролей → 24 графовых/статусные переменные (`§6.3` +
документированные расширения по фактическим ролям кода):

| Группа | Переменные |
|---|---|
| Сетка/каркас (§6.3) | `--chart-grid` (#F0F0F0→#262830), `--chart-border` (#E5E5E5→#2E3038), `--chart-reference` (#D4D4D4→#3B3E47) |
| Оси/подписи | `--chart-axis` (#171717→#CACCD4, §6.3), `--chart-axis-text` (#737373→#9A9DA9), `--chart-axis-muted` (#A3A3A3→#71747F) |

Светлые значения — **байт-инвариант** прежних литералов (светлая тема —
пиксельный инвариант). Механизм — скрипт-мигратор `scripts/task_dkt3/
hex_to_var.py`: замена только цитированных литералов в кодовых строках
(строчные и блочные комментарии пропускаются; исторические упоминания hex
в комментариях сохранены намеренно). Отчёт построчной сверки — вывод
скрипта, зафиксирован в worklog7.md.

### 2. Волновые фоны

`HomeWavesBackground.tsx` (14 stopColor + 3 stroke="#FFF") и
`NavigatorWavesBackground.tsx` (17 stopColor + 3 stroke="#FFFFFF"):
k-е вхождение цвета в порядке документа → `--wave-home-1…14`,
`--wave-home-stroke`, `--wave-nav-1…20`. Светлые значения == прежние
литералы; тёмные — системное преобразование с сохранением hue
(S→0.32, L→0.13; белый штрих → #2E3038): декоративные слои остаются
тонкой подложкой страницы #0B0C10, слоистая прозрачность (`stop-opacity`,
`stroke-opacity`) не тронута. Контроль яркости: все тёмные волновые
значения ≤ 0.25 относительной яркости (тест).

### 3. PNG-экспорт (§6.4, §10.1)

`packages/ui/lib/chartVars.ts`: световая карта `CHART_VARS_LIGHT`
(59 значений — зеркало `:root`-блока globals.css, синхронизация страхуется
тестом) + `resolveSvgVarsLight()` — клон SVG с резолвом `var()` в
конкретные значения по атрибутам `fill/stroke/stop-color/color/
background-color` и inline-style; переменные вне карты остаются как есть
(fail-visible). `ForecastExportMenu.downloadChartPng` резолвит клон ДО
сериализации. **§10.1: артефакт «всегда светлый»** (реализация по
рекомендации спеки; формально пункт остаётся открытым — переключение на
«как на экране» = локальная правка карты в резолвере). Canvas-заливка
#FFFFFF сохранена (единственный оставшийся hex-литерал — намеренно).

## DKT-4 — оболочки и сторонние поверхности

- **body-фон**: явные правила `body`/`.dark body` на токен `--c-page`
  (#FFFFFF / #0B0C10, каталог §6.1) — тёмная тема больше не зависит от
  дефолта UA. Токен добавлен симметрично в оба блока (паритет каталога —
  тест), согласован с `THEME_META_COLOR` (тест-сверка).
- **sonner (R-7)**: новый `ThemeToaster` (client) — `theme` prop из
  `useTheme()`; подключён в standalone-layout вместо голого `<Toaster/>`.
  Вне провайдера деградирует в светлый (ThemeContext) — безопасно везде.
- **ModuleNav/feed-scroll**: аудит — ModuleNav использует только токены
  каталога (bg-brand/white/neutral-*, text-brand → bright); feed-scroll
  уже ревизован в DKT-2. Правок не требуется.
- **meta theme-color**: управляется ThemeContext с DKT-1; embedded-пункт
  снят решением §10.2.
- **Embedded — решение §10.2 «v1 только standalone»**: точки монтирования
  не переносятся; контракт зафиксирован тестом (layout embedded без
  ThemeProvider/no-FOUC). DKT-3 embedded не ломает: `:root` байт-инвариантен.
