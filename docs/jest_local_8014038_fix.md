# JEST-LOCAL-8014038 — CRC-32 и бюджет локального Jest

База: `8014038fe40f4b2e399fb1104823e0c6d9ea7bd4`, 30.10.2026.
Синхронизация `git fetch origin main`, отдельное detached worktree;
предыдущие изменения сохранены. `AGENTS.md` прочитан, commit/push нет.

## ОС и фактические отказы

В `.github/workflows/jest.yml` текущего коммита матрица —
**`ubuntu-24.04` / `windows-2025`**, Node проекта — 22. Ubuntu 26 не вводилась.
Workflow этой задачей не меняется. Runtime Node самих Actions v6 и версия
Node, которой исполняются локальные тесты, являются отдельными настройками.

Приложенный локальный лог: **237 suites / 2740 tests, 4 failed suites /
13 failed tests**, сохранён в `protocols/user-local-failures.txt`.

- 11 ошибок в `rendererCore.test.ts` и `test_p8cert_oracles.test.ts`:
  `TypeError: node_zlib_1.crc32 is not a function`. PNG-фикстуры используют
  отсутствующий встроенный API. Ядро renderer также прямо импортировало его,
  поэтому исправление только конструкторов фикстур оставило бы ту же
  несовместимость в продуктовой pHYs-инъекции.
- FIFO-тест `useChartDetailData` заполняет 40+1 ключей, вызывая `waitFor`
  для каждого ответа. В контролируемой среде он проходил за 2163 ms;
  большая часть времени — последовательный polling. В логе тимлида
  тест превысил общий лимит 5000 ms.
- Один тест Валидации обходил все девять остановок и мастеров под общим
  лимитом 5000 ms. На этой машине он проходил за 687 ms; локальный timeout
  тимлида здесь не воспроизведён. Эти времена не являются оценкой его машины.

По [официальной документации Node](https://nodejs.org/api/zlib.html#zlibcrc32data-value),
`zlib.crc32` добавлен в 20.15.0 / 22.2.0. В присланном логе нет версии Node;
конкретную локальную версию утверждать нельзя. Воспроизведён именно механизм
отсутствия API: отдельный setup `without_native_crc.cjs` делает его undefined
в тестовом процессе, сохраняя остальной zlib. На исходном коде получены
**11 failed / 71 passed**, ровно те же CRC-падения. Таймауты в этом прогоне
не воспроизвелись. Setup не включён в обычную конфигурацию Jest.

## Решение и точки изменения

1. Прочитан лог, проверены SHA, правила, структура и обращения к CRC.
2. Чистый npm ci, RED исходного корпуса при отсутствующем native CRC.
3. Добавлены контрольные векторы и проверки для нового локального CRC-модуля;
   до реализации получен Import-RED (отсутствующий модуль), зафиксированный
   отдельно от содержательного RED 11 исходных тестов.
4. Реализован PNG CRC-32 в `apps/print-renderer/src/pngCrc32.ts`:
   отражённый полином `0xedb88320`, lookup table 256, initial/final XOR
   `0xffffffff`, unsigned результат. Вход — видимые байты Uint8Array/Buffer.
   Алгоритм соответствует [спецификации PNG](https://www.w3.org/TR/PNG-CRCAppendix.html).
   Native CRC больше не требуется ни ядру, ни его фикстурам.
5. Тесты импортируют **отдельный** bit-at-a-time oracle
   `scripts/testing/pngCrc32Oracle.ts`, который не импортирует продуктовый
   CRC-модуль. Оба закреплены фиксированными значениями: empty=0,
   `123456789=0xcbf43926`, `IEND=0xae426082`, бинарные байты;
   проверены subarray и детерминированный бинарный корпус.
   CRC PNG/pHYs, позиция чанка, идемпотентность и неизменность изображения
   продолжают проверяться прежними независимыми PNG-данными.
6. FIFO-тест теперь явно завершает mock-транспорт внутри awaited async act:
   все 41 ответа проверяются по payload и loading без опроса таймером.
   Усилены assertions: ровно 41 сетевой запрос, следующий старейший ключ
   остаётся cache hit, первый вытеснен и после сети даёт новый payload.
   Продуктовый хук не менялся. В адресном прогоне тест занял 20 ms вместо
   2163 ms на этой же машине; это не обещание времени на любом оборудовании.
7. Девять остановок Валидации переведены в `it.each`: каждый мастер проверяется
   после начальной гидратации на отдельном рендере с прежним лимитом.
   Сохранены все девять пар label/fix-button и наличие редактора. Проверки
   toggle, закрытия при смене остановки и отсутствия у «Типов данных» сохранены.
8. `jest.config.js` задаёт maxWorkers=2 и для обычного `npx jest`, как в CI.
   CLI override работает (проверены default=2 и explicit=3). Лимиты тестов,
   diagnostics и набор testMatch не менялись. Нет skip/xfail/исключения suites.

Новых runtime-зависимостей нет; package.json/lock и CI workflow не менялись.
В Dockerfile изменён только устаревший комментарий «Node 24 required for
zlib.crc32»; оба образа `node:24-bookworm-slim` сохранены.

## Риски и проверки

Риск неверного CRC закрывается фиксированными векторами, отдельным алгоритмом
оракула, прежними PNG-тестами и сравнением с native CRC текущего Node на
257 бинарных длинах. Риск ослабления FIFO закрывается проверкой сохранённой
записи и получения нового payload после вытеснения. Деление Валидации даёт
8 дополнительных test cases, сохраняя девять исходных остановок.

Адресный итог при принудительном отсутствии native CRC: **5 suites / 96 tests
GREEN**. Полный штатный корпус: **238/238 suites, 2754/2754 tests GREEN**,
98.864 s. Полный корпус без native CRC: **238/238 suites, 2754/2754 tests
GREEN**, 103.979 s. В обоих прогонах 0 failed/skipped/runtime errors.
Renderer build и typecheck обеих оболочек прошли; PGV-07 guard 41/41,
PGV-08 guard 48/48. Фактические счётчики/exit codes —
в `scripts/jest-local-8014038/protocols/summary.json`.
Ожидаемая арифметика: 2740 + 8 отдельных validation cases + 6 CRC cases = 2754,
237 + 1 CRC suite = 238 suites.

Тестирование без native CRC моделирует отсутствие конкретного API. Оно не
сертифицирует любые старые версии Node и остальные зависимости проекта.
Нативная машина тимлида и Windows-runner в этой сессии недоступны; версия
Node из его лога неизвестна. Docker/Chromium final-image не пересертифицируется.
Таймаут на полностью занятом/зависшем хосте нельзя исключить общим тестом.

## Применение

Распаковать ZIP поверх `8014038`, включая новые CRC-модули и полный журнал.
Из корня:

```sh
npm ci --include=dev --workspaces --include-workspace-root
npm run test:ci
```

Для отдельной проверки отсутствующего API:

```sh
npx jest --ci --setupFiles ./scripts/jest-local-8014038/without_native_crc.cjs
```

Версию Node можно проверить `node --version`; native API —
`node -p "typeof require('node:zlib').crc32"`. Исправление не требует менять ОС.
