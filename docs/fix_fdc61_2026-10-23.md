## 1. Находка (из акта DOCLOG-6-CERT, §5)

`diff_revisions(текущая, against=предыдущая)` возвращала
`claims.added` = утверждения, существующие в AGAINST и отсутствующие в
текущей, и `claims.removed` = наоборот; панель doclog6-diff
(DocumentationWorkspace.tsx) подписывает added → «Добавлено утверждений»,
removed → «Убрано утверждений». Зонд (`protocols/probe_findings.json`):
v1={A}, v2={A,NEW}; diff(v2, against=v1) клал NEW в `removed` → UI
показывал «Убрано: 1» при честном чтении «Добавлено: 1». Данные честны и
заморожены (recalculated=false), ни один claim не терялся, согласование/
архив не затронуты — находка низкой тяжести, семантика чтения.

## 2. Решение и обоснование

**Выбран вариант «фикс backend»** (из двух, рекомендованных актом:
поменять семантику diff_revisions ЛИБО подписи панели):

1. **API — первичный контракт.** Панель UI — один из потребителей;
   `GET /revisions/{id}/diff?against=` читают и прямые клиенты. Естественная
   конвенция «diff(target, against=base) = изменения от base к target»
   (как `git diff base..target`) должна жить в контракте, а не в подписях.
2. **Вариант «поменять подписи UI» оставлял бы инверсию в metadata
   from/to и validity_changed from/to** — отклик остался бы внутренне
   противоречивым (claims естественные, metadata — перевёрнутые).
3. **Подписи панели уже естественны** и закреплены UI-тестом
   (doclog6-lifecycle-ui.test.tsx: mock `added` = новое утверждение) —
   их правка сломала бы согласованность с UI-пином.

**Состав фикса** (единый согласованный контракт во всём отклике diff):

| Поле отклика | Было (инвертировано) | Стало (естественное) |
|---|---|---|
| `claims.added` | есть в against, нет в rev | появившиеся в rev относительно against |
| `claims.removed` | есть в rev, нет в against | существовавшие в against, отсутствующие в rev |
| `metadata[f]["from"/"to"]` | from = значение rev, to = against | from = значение against, to = значение rev |
| `source_cutoff.*`, `completeness.*`, `reproducibility.*` | то же (инвертировано) | то же (естественное) |
| `claims.validity_changed[].from/to` | from = rev, to = against | from = against, to = rev |

`recalculated=false` не менялся; наборы различающихся полей и тексты
claims не зависят от направления (ни один claim не теряется — подтверждено
зондом разрешения). Подписи/UI/mocks UI не менялись. Метод
`diff_revisions` получил docstring с контрактом направления; маршрут
`(§17)` в router уже честно делегировал сервису.

Пин направления закреплён **тройственно**:
- repo-сюита: `TestRevisionDiff::test_diff_direction_natural_semantics`
  (a35-дизъюнкт устранён — пин теперь живёт и в repo);
- оракул a35: эволюция пина на естественный контракт (docstring фиксирует
  историю эволюции после F-D6C1);
- контрактный документ: `docs/doclog6_approvals_archive.md`, D10 —
  направление задокументировано.

## 5. Попутная находка фикса: вырожденный исторический мутант M30

При эволюции якоря M30 установлено: **исторический мутант M30 был
вырожденным**. Его замена `if False:` (с двоеточием) внутри list
comprehension даёт **SyntaxError** — файл перестаёт импортироваться, и
обa канала «краснеют» collection errors. Классификация DUAL-KILLED в
кампании DOCLOG-6-CERT для M30 — артефакт вырожденности (любая поломка
синтаксиса даёт тот же результат; behavioral-проверка validity_changed
не выполнялась). Воспроизведено на файле из c9b87a1
(py_compile → SyntaxError, line 1693).

**Исправление корпуса:** мутант M30 заменён на семантически валидного
(`if False`, без двоеточия → validity_changed всегда пуст, файл
импортируется). Ремутация на исправленном дереве: **ORACLE-ONLY** —
честная классификация: в repo-сюите пина validity_changed нет (ловит
только оракул a35); пин a35 при переносе N1 в repo становится
дополнительным кандидатом (7-й к списку N1: a10/a22/a28/a32/a39/a40).
Исторические протоколы кампании (`mut_*.json`) НЕ переписывались — факт
зафиксирован новым протоколом `protocols/remut_fix_M30_validity_changed_off.json`.

## 6. Честные границы

- Направление diff **изменило публичный отклик API** (поля added/removed
  и from/to поменялись местами). Внешних потребителей, кроме панели UI и
  корпуса сертификатора, в дереве нет (проверено поиском); evidence-пути
  DOCLOG-4/5/6 diff не сериализуют. Потребители, полагавшиеся на
  инвертированную семантику, обязаны перейти на естественную — это и есть
  цель исправления.
- Ревизии в панели diff сравниваются с «предыдущей версией» по version_no
  (UI); против произвольной ревизии — через параметр `against` (контракт
  не изменился).
- Пересертификация адресная (по плану акта для пункта (1)): корпус 79/79
  на своих данных + ремутация diff-мутантов + дельта-0 полного tests/
  против базы c9b87a1. Полная мутационная кампания (38+3) не повторялась
  — вне адресного контура; якоря остальных 35 боевых мутантов проверены
  MV1-паритетом (ровно одно вхождение, 33/33 LIFECYCLE + ROUTER/JOBS/
  SECURITY не затронуты фиксом).
- pgm-зеркала (PG-прогон) не затрагивались: fix не меняет миграции/схему.
