## 1. Предмет сертификации

Задача A (spec_progress_target_column.md §4-A, сертифицированная
редакция; правки R1–R4 акта PROGR-25-SPEC-CERT учтены; план
plan_progress_target_column.md §1): после успешной загрузки (upload И
demo) бэкенд применяет детерминированное правило кандидатов —
**кандидаты = числовые колонки фрейма − `session.date_column` − колонки
реестра производных**; при ровно одном кандидате фиксирует признак с
`source="auto"` и сеет программное событие `target_column_changed`
(payload `{target_column, source:"auto"}`, `stage="validation"`,
`node_id=None`, фиктивный POST запрещён); при 0/2+ — честное «не
выбран». Контракты: аддитивные Optional-поля
`target_column_source` (SessionStateResponse, TargetColumnResponse),
`target_column`+`target_column_source` (ProgressTraceResponse — носитель
шапки задачи B), `payload_keys` ручного маршрута += `source`; restore и
`set_dataset` не меняются по контракту; имя-исключение date-подобных
снято (R4).

Контрольные свойства задачи A:
- **Р1 единая точка правила**: `apps/api/target_column_rule.py` —
  `numeric_columns` / `target_column_candidates` / `suggest_target_column`
  / `auto_fix_and_seed`; recommendation и фиксация из одного правила
  (вторая реализация запрещена спекой);
- **Р2 точки фиксации**: `handle_upload` (`upload_common.py`) И demo
  (`POST /v1/session/demo`, правка R2); restore — своим путём, без
  второго события;
- **Р3 событие**: программный посев `make_trace_event` в точке фиксации,
  `actor="system"`, `ensure_run_id()` до посева (run_id общий с
  `upload_completed`);
- **Р4 контракты схем/канала**: три схемы аддитивно Optional;
  `payload_keys` ручного маршрута += `source` при legacy-payload без
  `source` (ответ маршрута ключ не несёт — «отсутствие = user»);
- **Р5 совместимость**: старый корпус без поля читается как `user`;
  `set_dataset`/convert-types сбрасывают цель И источник; re-upload —
  сброс трассы слоя 1 (канон PROGR-3) + авто-фиксация нового фрейма.

## 7. Находки

- **F1 (материальная, требует исправления до выката задачи B в
  production):** `target_column_source` НЕ сериализуется — в
  `session_to_dict` ключ отсутствует, в `session_from_dict` не
  восстанавливается. В памяти-бэкенде (песочница/тесты) не проявляется;
  в production-пути RedisSessionStore (Upstash через render.com) каждый
  цикл save→get теряет происхождение: авто-выбор читается как legacy
  None («user») → приёмка A «upload → /current отдаёт
  target_column_source="auto"» в production НЕ выполняется после
  первого roundtrip; шапка задачи B не покажет «(авто)», Наставник (C)
  не отличит происхождение. Доказательства: оракулы D1 (to_dict/
  from_dict) и D2 (Redis save/get на fakeredis); изоляция — D3
  (остальные поля того же документа сохраняются). Фикс точечный:
  одна строка в `session_to_dict` (`"target_column_source":
  session.target_column_source,`), одна в `session_from_dict`
  (`target_column_source=d.get("target_column_source"),` — backcompat
  дефолт None для старых документов) + repo-тест roundtrip; миграции не
  требует (аддитивное поле, документ схемы v3 читается).
  Вердикт по ядру задачи A — PASSED; выкат задачи B (шапка «(авто)»)
