## 2. Что сертифицировано (факты о поставке, подтверждённые корпусом)

1. **Синхронная заморозка** в момент capture честна: confirmed_at — session-факт
   (точное равенство с captured_at capture-ответа, ORACLE A2; время промоушена не
   подставляется — мутант M03 DUAL-KILLED); flags.created/reused — по created_snapshot,
   unchanged не заявляется (A-оракулы + валидатор); context — текущий на момент
   заморозки; panel entity_id = entity_column (AC14; мутант M09 DUAL-KILLED).
2. **Траектория «на момент подтверждения»**: stage_refs указывают на rs-записи ИМЕННО
   снимков соответствующих этапов (wrong-ref мутант M02 убит ТОЛЬКО ORACLE-каналом —
   repo-корпус поставки сверяет только формат rs-*); фильтр `captured_at <= confirmed_at`
   честен (мутант M04 DUAL-KILLED; tie-break «последний в append-only истории» —
   ORACLE-оракул).
3. **Reused handoff (AC11)**: новая физическая копия паспорта не создаётся
   (passport-артефактов ровно 3 в сценарии возврата ряда); popутный фикс
   `stage=snapshot.stage` устраняет passport-receipt легитимного reused-состояния
   (мутант M21 ORACLE-ONLY — repo-оракул слеп к receipt, см. N-P4C5).
4. **Идемпотентность §8**: durable checkpoint_id = `pck-` + session-id (мутант M20
   DUAL-KILLED); rs-записи идемпотентны по `pgv-passport:{snapshot_id}`, существующая
   запись не переписывается задним числом (в т.ч. при позднем появлении паспортного
   артефакта — content-гэп честен); повторная заморозка с другим payload — конфликт
   без записи (repo-тест поставки).
5. **AC12/честные отказы**: corrupt confirmed_at → PromotionUnavailable, НИЧЕГО не
   регистрируется, wall-clock не подставляется (ORACLE A6; мутант M08 ORACLE-ONLY);
   честный недобор траектории (start→modeling_entry) — info-skip БЕЗ durable-receipt
   (ORACLE A5/A8 notify-путь; мутант M11 ORACLE-ONLY после эволюции корпуса).
6. **R4-изоляция вселенных** (статика S3): panel-контур читает только
   panel_passport_history, single — passport_history; science-функции не импортируются
   (AC06; статика S4); заморозка не мутирует сессию (U1).
7. **Субстрат AC09**: durable-чекпоинт и rs-записи читаются после утраты
   session/Redis (repo + ORACLE-потоки).

## 7. Находки (акт §7)

**F-P4C1 (средняя; класс F-P2C2 «контракт не enforced» + молчаливый пропуск).**
`backfill_passport_checkpoints` читает несуществующее поле session
`panel_passport_checkpoints` (реальное — `panel_entry_checkpoints`): панельные
чекпоинты НИКОГДА не добираются sweep-каналом; они не попадают ни в frozen, ни в
skipped (молчаливо игнорируются). Нарушены собственный контракт модуля/доки поставки
(«single + panel вселенные») и критерий §13 «retry без capture» для panel_entry:
панельный чекпоинт, чья синхронная заморозка сорвалась (transient) или легаси-сессия
до поставки, не получит durable-представление никогда. Свидетельства: P1, B1–B3 RED,
M01 SURVIVED. Мёртвый сломанный тест-хелпер `_seed_panel_checkpoints` repo-корпуса
(вызвал бы ValueError: panel_entry вне PASSPORT_STAGES) — след задуманного и не
написанного панельного backfill-теста (N-P4C3).

**F-P4C2 (средняя; нарушение per-entry устойчивости sweep-канала).** Backfill ловит
только PromotionUnavailable; любой прочий сбой одной записи (ArtifactPayloadInvalid —
валидационный отказ payload при битой легаси-фактуре, например утраченные
panel_columns/dataset; ArtifactConflictError; KeyError битой session-записи) прерывает
ВЕСЬ добор: остальные легитимные чекпоинты не доставляются, каждый следующий sweep
получает тот же durable-receipt на весь backfill — доставка не восстановима. Прецедент
паттерна — per-entry try/except в sweep-цикле notify_modeling_artifacts_updated
(backtests/cards/forecasts), которому backfill обязан паритетом. Свидетельства: P2,
B4/B5 RED.

**F-P4C3 (низкая; документная честность, класс F-P3C2-подобный).** Докстринг
`freeze_passport_checkpoint` утверждает при честном недоборе «вызывающий
гарантированно ничего не записал» — фактически rs-записи вовлечённых снимков
(подтверждённый, previous, уже обработанные этапы) создаются ДО отказа на недостающей
точке траектории (P3). Rs-записи — честные адресуемые факты существующих снимков (не
фабкация), идемпотентность не нарушена, поведение приемлемо; лжёт контракт-текст.
Фикс — документация (модуль/док поставки), не поведение. Свидетельства: P3, B7/B8 RED.

**Наблюдения (вне скоупа исправления этой сертификации):**
- N-P4C1: при сбое register чекпоинта (после создания rs-записей) rs-факты остаются —
  природа адресуемых фактов; документировать (частично пересекается с F-P4C3).
- N-P4C2: PostgresSnapshotRegistry._record_from_row не восстанавливает
  completeness.missing_mandatory (субстрат PGV-02; Memory/Postgres-паритет — пины
  PGV-02; rs-записи создают missing_mandatory=[]).
- N-P4C3: мёртвый сломанный хелпер `_seed_panel_checkpoints` repo-корпуса — маркер
  отсутствия панельного backfill-покрытия (связано с F-P4C1).
- N-P4C4: unchanged-флаг не производится ни одним путём поставки — задекларированная
  граница поставки (подтверждена, не дефект).
- N-P4C5: дефекты оракулов repo-корпуса поставки: spy-фильтры
  test_start_only_flow_honest_skip_without_receipt (kwargs.operation) и
  test_reused_handoff... (косвенно) смотрят несуществующие kwargs-ключи — receipt
  (operation в details, producer_key в resource_id) невидим; кампания показала M11/M21
  SURVIVED против repo-канала; ORACLE-канал сертификации усилен и ловит. Исправление
  repo-оракулов — вне скоупа сертификации (продуктовое дерево не меняется), передаётся
  в план PGV-04-FIX опционально.
