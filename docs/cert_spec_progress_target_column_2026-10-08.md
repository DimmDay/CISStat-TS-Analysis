## 2. Расхождения спеки с кодовой базой (сказано прямо, по требованию тимлида)

**Р1 (блокирует приёмку §2.2, не отражено в плане задач). «Неоднозначный случай — тихого выбора нет» недостижим задачами A–D в текущей редакции.** Сегодня тихий выбор в неоднозначном случае существует ДВАЖДЫ: (а) бэкенд отдаёт ненулевой `suggested_column` при 2+ числовых («первая не-date-подобная» — рантайм-доказательство протоколом §4: [year? нет — date,value,price] → suggestion=value); (б) хук авто-POSTит эту рекомендацию безусловно (useTargetColumn.ts:139). После PROGR-25-A бэкенд перестанет фиксировать в неоднозначном случае, но хук продолжит — «Файл с несколькими числовыми колонками: панель показывает „не выбран"» (§7) НЕ выполнится. Требуется явная подзадача (естественно — в A или B): снять авто-POST из хука либо ограничить его однозначным случаем, оставив suggestion как отображаемую рекомендацию селектора. Одновременно решается «хук использует его же для рекомендации — вторая реализация запрещена».

**Р2 (средний). Точка фиксации — не одна: `set_dataset` вызывается из трёх мест.** Спека: «после успешной загрузки датасета бэкенд применяет правило». Фактически `set_dataset` зовут: handle_upload (upload_common.py:166 — production-путь UI), demo-эндпоинт POST /v1/session/demo (session.py:594), restore (progress.py:1146 — там target_column восстанавливается из run.target_column СВОИМ путём, конфликта нет). Если правило встроить только в handle_upload, кнопка «Попробовать на демо-данных» останется с «—». Рекомендация: единый хелпер фиксации, вызываемый из handle_upload И demo-ветки; restore — без изменений.

**Р3 (средний). «Фиксация идёт тем же путём, что и ручная (target-column)» — механизм записи события не выводится из буквы спеки.** Ручной путь — POST-маршрут /v1/session/target-column, чьё событие пишет trace_hook по строке TRACE_ROUTES (trace_hook.py:225-229, payload_keys=("target_column",)). Авто-фиксация внутри upload-ответа этот маршрут не проходит — событие target_column_changed(source=auto) после загрузки само не возникнет. Спеке стоит зафиксировать механизм явно: либо программный посев make_trace_event в точке фиксации (прецеденты: PROGR-16-A отчёты фактов, restore run_resumed), либо расширение TRACE_ROUTES upload-маршрута. TDD-критерий A («после загрузки … событие source=auto») это подразумевает, но буквой не держит — риск второй реализации записи события.

**Р4 (низкий). Определение кандидатов требует уточнения реализации, а не только постановки.** Спека: «за вычетом колонки даты и колонок реестра производных». Сегодня: `_get_numeric_columns` — ВСЕ числовые (routers/session.py:3966-3974); `_suggest_target_column` исключает только date-ПОДОБНЫЕ ПО ИМЕНИ (_DATE_LIKE_KEYWORDS), фактическую `session.date_column` не вычитает, о реестре производных (PROGR-24, session.derived_columns) не знает; сигнатура — чистая функция от списка имён. Для правила A хелперу нужен доступ к сессии (date_column + derived_columns_in_frame — канон задачи A ORIGIN-A). Рантайм-подтверждение: [year,value] → suggestion=value (имя-исключение работает), производноподобные исходные колонки (канон «не угадываем по суффиксу») suggestion сегодня захватывает.

**Р5 (низкий, констатация). PROGR-25-C «Условия читают уже посчитанные факты, нового I/O нет» — подтверждено с уточнением носителя.** phase_text: условия STAGE_PHASE_TEXT_RULES (mentor_rules.py:1104-1130) получают (summary, events); source доступен из payload события ПОСЛЕ аддитивного расширения payload_keys (Р3-контракт) — I/O не нужен. status_reason: `_stage_level_reason_updates` (node_status.py:309-354) читает payload.target_column, носитель (validation, sufficiency) — TARGET_REASON_STAGE_NODE:285; дополнение «(авто)» из payload.source — аддитивно. Нюанс, спеке известный: событие авто-POST ВСЕГДА stage="validation" (атрибуция маршрута, не вкладки) — рантайм-пин протокола §3.

**Р6 (информационное). Мелкие сверки, существенных расхождений нет.** Нумерация PROGR-25 свободна (worklog8/9 не содержат). Прецедент `confidentDateCol` подтверждён (TsAnalysisUpload.tsx:236, 470-472 — «доверяем осознанному выбору, confidence — только предупреждение»). Схемы TargetColumnResponse/SessionStateResponse/ProgressTraceResponse — аддитивное расширение безопасно (Optional-поля; тест «ровно 7 полей» движка не затрагивается — payload-ключ, не поле движка). Прочерк «—» остаётся при отсутствии датасета — согласовано с рендером «Датасет: … ?? "—"». Перезапрос /trace на КАЖДОЕ открытие панели (ProgressDrawer:119-148) делает приёмку B «повторное открытие → новое значение» достижимой. Спека: «нарезка… PROGR-24 последняя занятая» — совпадает с журналом; термины «исследуемый признак»/«подходящая числовая колонка» согласованы с кодом (TargetColumnResponse.docstring).
