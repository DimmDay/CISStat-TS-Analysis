| H28 | Изоляция изначально GREEN. Расширенный сценарий с ответом POST в следующей задаче event loop воспроизвёл отказ в полном Jest: 2 POST вместо 3. Добавлен положительный контроль исполнения, явные spawn error/stderr/status и путь с пробелами/апострофом. Продакшен launchGuard не ослаблялся. Это усиление теста, а не доказательство причины исходного отказа cancellation на машине пользователя. |

## Воспроизведение

Из корня: `npm ci --ignore-scripts --no-audit --no-fund`, затем `npx jest --maxWorkers=2`.
Для тестов реального shell нужны `/bin/sh` и POSIX utilities runtime контейнера (Linux).
На машине без этих предпосылок нужен Linux-контейнер/runner; отключение тестов не предложено.
Здесь `/tmp` и `/proc` отсутствуют; `TMPDIR` задан на доступный каталог сессии.

`npm run build --workspace=@cisstat/print-renderer` и `npm run typecheck:all` проверяются отдельно.
Обе Next production builds попытались выполнить; обе BLOCKED средой:
`ENOENT uv_resident_set_memory` при обращении Next к `/proc`. Это не успешная сборка и
не доказательство продуктового дефекта. Подмена memoryUsage или отключение проверок не выполнялись.
Docker/Chromium final-image сертификация PGV-08 данной задачей не пересматривается.
Предыдущий статус BLOCKED остаётся в силе.
