## Решение и точки изменения

Единый scientific coordinator использует действующие RequestContext → current Account caps → authorize_run_access → access_registry.evaluate_entry. Не новый реестр ролей/тарифов/владения. Научные routers internal/public/models/diagnostics/session/modeling/forecasting/tasks/upload_db и research progress получают общий ScientificRoute и router dependency. Route preflight до JSON/multipart parsing проверяет credential/current Account/object/stage/capability; dependency перед handler нормализует фактическую нагрузку. Service admin progress сохраняет существующий named ADMIN+MFA gate; health/education/auth/DOCLOG служебные политики не превращаются в коммерческие научные стадии. Служебная трасса/метаданные research progress остаются под current Account/object/history policy; они не дают нового разрешения fit или доступа к guarded forecast CSV/Model Card.

Production required/scoped default enforce. Anonymous/research-cookie/ENV не заменяют личный вход; browser internal/session требует named auth_session, programmatic bindings требуют durable api_key + scopes + can_use_api. Разные credentials не объединяются. В advisory dev разрешён прежний unbound compatibility; предъявленные named/durable credentials всегда идут через guard. Явный legacy_dev в protected profile запрещён. Никакого production off/shadow bypass.

Object gate читает существующую AnalysisSession/ResearchRun без создания/claim и проверяет Account/tenant прежде plan/модельных аргументов. Foreign/absent uniform404. Run URL загружает собственный session context, а не browser claims; history/restore ограничен can_save_history, текущий active run не считается новым analysis. Динамические stage IDs проходят scientific allowlist, application aliases используют существующие application policies; causal Demo запрещён, научная Granger и DOCLOG monitoring не становятся платными из-за имени.

Нормализатор использует фактическую длину DataFrame/переданной stateless series, сохранённую validation_strategy, фактические folds/horizon+gap/period и выбранные server artifacts. Card/forecast/diagnostics/selection/list/state не доверяют browser model_id/params_source или профилю. Неизвестное происхождение сохранённого baseline не считается default. Снижение плана проверяется также на polling/read/export/forecast/restore, не только на запуске fit. Метаданные candidates не являются разрешением fit: отдельная admission для каждого запуска; запрещённые действия кандидатов маскируются в ответе.

В дополнение к ingress guard ContextVar request admission проходит к synchronous scientific engines. Перед реальным backtest/diagnostics/forecast повторно проверяются фактические model/rows/folds/horizon/period/params. Это закрывает изменение validation/model workload между ingress и выполнением. Межзапросный positive cache отсутствует. Worker authority/revoke-after-admission/fencing/settle остаются AUTH-13, атомарные CU/analysis/API quotas — AUTH-12; здесь не имитируется бюджет.

Baseline разрешён по точному allowlist AUTH-01 (naive/seasonal_naive/drift) и конечным потолкам. Старый can_train_models adapter не блокирует их в programmatic API; advanced/tune проверяются отдельными caps. Bootstrap не добавляет mean в ограниченный baseline cohort. Placeholder train в enforced profile не сообщает о несуществующей работе. Sensitivity parameter search требует tuning; restore требует history. Глобальный legacy PATCH rules override не изменяет общие правила из protected Account (safe denial); современный session-scoped validation rules endpoint сохраняется.

Upload file/DB/demo проверяют текущие own-upload права и фактические rows до регистрации файлов/данных/session mutation. DB probe и load проверяются до connector creation; row_limit ограничивается текущим server cap, row count после чтения перепроверяется. Запрет can_use_api относится к programmatic credential, не ко всем browser HTTP запросам.

## Эксплуатация и проверяемые границы

Миграции 0019–0024 и AUTH-10 authority уже в базе bf57630; AUTH-11 не меняет SQL schema, cookie format, очереди или обязательные env. Пересобрать api и web. `CISSTAT_SCIENTIFIC_GUARD_MODE` необязателен: required/scoped автоматически enforce; off/shadow/legacy_dev там дают 503, а не обход. `/health/ops` → identity.scientific_guard показывает режим, не доказывает доступность PostgreSQL authority. Для protected scientific browser теперь обязателен существующий named вход; публичная anonymous Demo-витрина остаётся AUTH-15. Старые research-cookie-only сценарии в production осознанно получают401.

На ограниченном плане отсутствующие server defaults folds/horizon/models ограничиваются паспортом baseline. Явные analyst CV значения не обрезаются: превышение даёт402. Все model fits повторно проверяют реальные параметры. Legacy global PATCH rules/update и placeholder train в enforced profile дают501; работать с правилами через существующий session-scoped endpoint. Неизвестное происхождение старой ModelCard даёт отказ на ограниченном плане: данные не подделываются и автоматически не «исправляются» в baseline.

Существующий AUTH-09/10 PostgreSQL fixture содержит authority/ownership, но не полный artifact promotion catalogue0007; его предупреждение о durable promotion не является проверкой публикации артефактов. В AUTH-11 доказаны Account/object admission и реальное вычисление baseline, а не worker fencing, atomic accounting или полный production artifact recovery. Нет межзапросного positive cache; отзыв после admission в уже запущенной фоновой работе отдельно AUTH-13. Проверка native выполняется на disposable БД. AUTH-12/13 не объявляются реализованными.

Маршруты: 239 HTTP методов, 243 bindings, 173 guarded API bindings; HTTP delta пустой. Два внутренних review surfaces добавляют полный inventory574 без новых HTTP endpoints.
