# Акт независимой сертификации PGV-06 «Pure comparison resolver»

**Дата:** 2026-10-29. **Сертификатор:** независимый контур сертификации
(метод «мутанты на своих мутантах, оракулы на своих данных»; прецеденты
PGV-02-CERT/03-CERT/04-CERT/05-CERT). **База:** main@cb46e3a (PGV-06 —
Pure comparison resolver), рабочее дерево чистое, субстрат не менялся.

**Предмет поставки:** apps/api/passport_comparison.py (НОВЫЙ — резолвер
`pgv.passport_comparison/1`), apps/api/routers/session.py (изменён —
orchestration через versioned adapter, 2 строки), корпус поставки
tests/api/test_pgv06_passport_comparison.py (32), docs, scripts/pgv06/.

**Критерий готовности (§13):** «Прежняя семантика refs,
cutoff/reuse/incompatible contexts проверены».

---

## 1. Постановка и граница сертификации

§9 spec_passport_graphics_visual.md: общий pure comparison engine
выделяется из session orchestration (существующая `_compare_ts_props`
через versioned adapter, без дублирования формул в TypeScript); вход —
immutable refs; frozen PassportComparisonSnapshot/1 (ordered refs/path,
checkpoint metadata, numeric/category/list/qualitative deltas,
method/schema versions, gaps/context); default resolver использует
trajectory checkpoint; несовместимые target/entity/units/schema → 409
comparison_incompatible; cross-context — только явный режим с
маркировкой; panel entities не смешиваются; unchanged modeling_entry не
добавляет нулевую дублирующую колонку, отдельная строка confirmation;
missing validation — gap, не ноль; complete/partial честны; definitions
с zero-denominator reason; цвет delta ≠ значимость.

Применимые AC: AC13 (виды изменений/zero-denominator/несовместимость),
AC14 (панель не смешивается), AC10 (cutoff — не latest каждого stage),
AC11 (reused/unchanged без четвёртой копии), AC12 (gaps честны),
AC06-дух (read-only, без пересчёта науки), AC07-дух (409-семантика на
несовместимости), AC18-дух (uniform-отказ без дисклоужения).

Границы: P02-документы/lifecycle — PGV-13; печатная композиция — PGV-07;
пагинация — PGV-14; UI — PGV-15; HTTP-экспозиция 409 — с эндпоинтами
PGV-13. Резолвер сертифицируется как library-level контракт.

## 3. Оракулы на своих данных (Class A — 28, все GREEN ×2)

tests/api/test_pgv06_cert_oracles.py, namespace p6cert-*/RUN-P6CERT*
(дизъюнкт от продукта и корпусов пинится статикой U1 с
анти-самотриггером — корпус не импортирует scripts/tests).

U-блок (инварианты самой сертификации): U1 дизъюнкт+анти-самотриггер;
U2 пины контракта (schema/engine frozen); U3 AST-гейт резолвера (без
SessionStore/pandas/numpy/redis); U4 orchestration не ссылается на
приватный движок напрямую; U5 все поля frozen-снапшота §9; U6
definitions-пины (формула, граница 1e-10, 0.0/100.0, цвет ≠ значимость).

A-блок (приёмочные оси на собственных данных сертификатора — серия
seed 20261102, иной формы, чем у поставки): A1 zero-denominator ==
фактическому движку (0/5→100.0, 0/0→0.0, граница 1e-11, отрицательный
базис 133.33) + parity; A2 виды изменений на реальных паспортах
(AC13); A3 матрица несовместимостей 4 оси + XOR-честность (None — не
значение) + cross-context явный режим (AC13); A4 панельная вселенная
(AC14: 1 точка/0 пар/complete/universe=panel); A5 cutoff ×2 чекпоинта —
две независимые траектории, ранняя стабильна, exit обновляется только
во второй (AC10); A6 unchanged-reuse без дублирующей колонки +
confirmation (AC11); A7 reused-возврат — алиас validation-записи,
previous_ref = exit (AC11); A8 дыра в середине explicit — без
молчаливого моста, здоровые соседи строятся (AC12); A9 corrupt-байты —
content_corrupt (классификация точная), затронутые пары не строятся
(AC12); A10 dangling stage_refs — partial с перечнем (AC12); A11
complete ⇔ ноль gaps; A12/A13/A14 панель/доступ/uniform-честность
чужого ref (AC18-дух — дифференциально: чужой существующий ==
отсутствующий по reason И detail); A15 read-only + детерминизм
(AC06-дух); A16 режимы XOR, absent → None; A17 method_versions AS-IS
(legacy_unknown не выдуман); A18 инверсия дельты в обратном explicit
порядке (направление честное); A19 паритет сессийного эндпоинта ==
adapter == движок; **A20** cross-context через резолвер на crafted
durable-артефактах — маркировка пары И снапшота (ремутация M07/M27);
**A21** content-дыра внутри stage_refs чекпоинта — пары через дыру не
строятся и не падают, здоровая соседняя строится (ремутация M12);
**A22** повторный ref — алиас без нулевой пары, IDs доступны
(ремутация M15/M16/M20).

## 4. Мутационная кампания «на своих мутантах» (scripts/pgv06cert/)

28 боевых мутантов над КОДОМ ПОСТАВКИ passport_comparison.py (+session
для M25) + 3 контроли K01–K03. Каналы: REPO = 32 теста поставки,
ORACLE = Class A сертификатора. Протокол: scripts/pgv06cert/protocols/
mutation_campaign_protocol.txt (+журнал JSONL).

**Итог: 20 DUAL-KILLED + 5 ORACLE-ONLY-KILLED + 3 ALIVE; контроли 3/3
ALIVE.**

- DUAL (20): M01–M06 (оси несовместимостей/кросс-контекста), M08–M11
  (parity/unchanged-машина), M13 (мост в explicit), M17–M19
  (completeness/confirmation), M23–M25 (порядок этапов, gaps,
  adapter-обход), M26-производные оси.
- ORACLE-ONLY — пойманы ТОЛЬКО независимыми оракулами (репетиция
  ценности независимого корпуса): M07 (потеря allow_cross_context в
  explicit — маркировка), M12 (падение резолюции на content-дыре
  траектории вместо честного gap), M21 (переклейка content_corrupt →
  content_missing), M22 (снятие XOR режимов), M27 (потеря снапшот-
  уровня маркировки cross_context).
- Ремутация (мутанты на своих мутантах): первый проход дал 7 ALIVE —
  4 из них (M07/M12/M21/M27) оказались ПРОБЕЛАМИ оракулов
  сертификатора; добавлены A20/A21 + ужесточён A9; вторым проходом
  добавлен A22 (пины aliases/IDs после выявления REPO-ONLY M15/M16/M20
  в первом проходе). Финальный канал ORACLE самодостаточен: REPO-ONLY=0.
- ALIVE (3 — эквивалентные/средовые, не дефекты корпуса): **M14** —
  эквивалентный (guard `old/new is None` перекрывается следующим
  guard'ом present_by_position; defense-in-depth); **M26** —
  эквивалентный (str()-коэрция refs не меняет поведение на строковых
  входах — единственных валидных); **M28** — средово-ограниченный
  (session_id="" неотличим в memory-режиме авторизации по субъекту;
  session/API-key режимы вне сертифицируемой среды — известная граница
  серии).
- Контроли K01–K03 (докстринг, комментарий, порядок ключей definitions)
  — ALIVE: каналы не «убивают тривиально».

Валидность кампании: первые попытки выявили дефект запуска каналов
(опечатка `-tb=no` → usage-error убивал каналы мгновенно; зафиксировано
и исправлено на `--tb=no`) и гонку с фоновым процессом; финальный
протокол получен при чистом дереве, оригинал восстанавливается
гарантированно (finally + md5-сверка на каждом шаге).

## 5. Class B: находки (tests/api/test_pgv06_cert_findings.py)

**F-P6C1 (низкая; доступ/диагностика — класс AC18-дух).**
Trajectory-режим резолвера копирует reader-гэпы AS-IS, а
PassportHistoryReader (`_snapshot_record`, субстрат PGV-05) даёт РАЗНЫЕ
человекочитаемые detail-строки: чужой существующий ref — «rs-запись не
принадлежит запуску…», отсутствующий — «rs-запись отсутствует в
реестре…». Машиночитаемый reason uniform (missing_snapshot_record), но
detail дисклоужирует СУЩЕСТВОВАНИЕ чужой записи владельцу другого run'а
(через crafted чекпоинт со stage_refs на чужой ref). В explicit-режиме
резолвер сам строит uniform-гэпы — утечки нет (проверено
дифференциальным оракулом A14); дыра — именно в AS-IS-пробросе
reader-гэпов траектории. Эксплуатационный риск низкий (нужно знать/
угадать валидный чужой ref; reason-коды uniform; API-слой не затронут),
но по духу AC18 detail обязан быть uniform. **Фикс (одна строка в
субстрате или нормализация на границе резолвера):** uniform-деталь для
всех вариантов missing_snapshot_record. Тест B1 (дифференциальный:
одинаковые payload'ы, отличается только start-ref чужой/отсутствующий)
— RED сейчас, обязан стать GREEN после PGV-06-FIX без ослабления
смысла. Наблюдение: та же различающая диагностика существует на уровне
reader'а (read_passport_snapshot) — вне буквального контракта PGV-06,
фикс на границе резолвера закрывает surfaced-путь.

## 6. Honest-границы сертификации

1. Memory-сторы; живой PostgreSQL/docker/Render не задействованы
   (паритеты — пины PGV-02/04-CERT).
2. Кампания ограничена кодом поставки (passport_comparison.py +
   call-site session.py); субстрат (reader/checkpoints/артефакты) не
   мутировался — сертифицирован PGV-02/04/05-CERT.
3. M28 (session_id в явном вызове чтения) — эквивалентен только в
   memory-режиме авторизации; в API-key/session-режимах семантика не
   проверяема в этой среде (граница серии).
4. units-ось несовместимости честно непроверяема (durable-записи units
   не записывают) — зафиксировано поставкой, подтверждено сертификатором
   как честный предел, не фабкуется.
5. Манифест sha256 не ведётся (прецедент серии, указание тимлида).

## 7. Вердикт

**Сертификация ПРОЙДЕНА с одной низкой документно-диагностической
находкой.** Поставка честна по всем проверенным осям: §9-контракт
(versioned adapter, формулы не дублируются — 20/20 поведенческих
мутантов убиты обоими каналами), прежняя семантика refs/cutoff/reuse
(AC10/AC11 подтверждены на независимых данных), несовместимые контексты
(AC13/AC14: 4 оси + XOR-честность + cross-context маркировка), gaps/
completeness (AC12), read-only/детерминизм (AC06-дух), uniform-доступ
(AC18-дух, кроме F-P6C1). Блокирующих дефектов нет; F-P6C1 (низкая)
устраняется однострочным фиксом и оформлена как Class B RED-до-фикса.
5 инвариантов пойманы ТОЛЬКО независимыми оракулами (M07/M12/M21/M22/
M27) — подтверждена ценность независимого канала.
