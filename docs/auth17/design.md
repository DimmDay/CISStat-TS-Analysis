# AUTH-17 — Invitations, seats, OWNER transfer

База201a3b1f12eac55525fb07301b5e37f8e962d938. Логический service внутри FastAPI, текущие Identity/Account/Membership/AuthSession, AUTH-12 budgets, mandatory audit outbox. Без commit/push/VM.

Seats — подтверждённая capacity (включая OWNER), active membership занимает место. Invitation не резервирует место и не создаёт identity/seat/CU. Принятие под Account lock проверяет current inviter OWNER, target identity/verified email, capacity и uniqueness. Repeat consumed invitation не восстанавливает удалённое membership. Pending invite TTL≤7d, batch/list bounds, verifier256-bit SHA256, raw secret только один ответ; в URL/лог/cache/storage browser не передаётся. Email соответствует только уже подтверждённому контакту той же signed-in identity; unknown/ambiguous email не склеивает identity. UUID приглашение доступно существующим personal users до AUTH-19. Рассылка не включается.

Self-service MONO↔MULTI сохраняет account/tenant/run IDs и историю. Demo/forum/service identities не управляют team. MONO→MULTI явно подтверждает совместный доступ к account-owned исследованиям; legacy unresolved не мигрируют. MULTI→MONO: capacity1/active member1, нет running/uncertain reservations/workers, pending invites отзываются. OWNER transfer требует recent personal login≤5m и свежего MFA, если factor настроен. Удаление последнего OWNER запрещено на service и прежнем deferred SQL guard. Removal/transfer отзывают affected account sessions/challenges, API key revoke поддержан AUTH-10 trigger; sibling accounts не затрагиваются. Pending invites отзываются при transfer/removal/conversion, чтобы прошлые разрешения не оживали.

Browser seats request создаёт immutable pending intent/outbox, не меняет capacity/quotas. Лишь trusted interactive operator после внешней подтверждённой entitlement применяет request с unique confirmation_ref и CAS; HTTP не принимает payment proof. Provider quote/payment/price/proration/credit относятся к AUTH-18/21. AUTH-17 не начисляет CU ни при accept, ни при seat churn: spent/reserved/limits/ledger сохраняются. Это явный безопасный handoff, а не бесплатный автоматический purchase. Existing seats не переименовываются в доказанную оплату и исторические финансовые credits не выдумываются.

Каждая mutation с reason, expected entitlement version (accept проверяет invitation/capacity под lock), server canonical command и actor/account/key/body digest. Atomic result receipt + state + audit. Replay с другим payload409; token issue replay не раскрывает старый raw token и не выпускает второй. Personal authentication перечитывается внутри transaction; sorted Identity locks→actor SID→Account, membership read under parent lock. Missing/foreign404, no auth401, permission403, conflict409, authority503. Не монтировать trusted AUTH-08 writers как HTTP.

Account selection создаёт новый opaque SID, отзывает старый, переносит исходный auth_time/MFA/family и absolute deadline (не продлевает login). Server clears research pointer/CSRF; UI reload сбрасывает account caches. Accept не выбирает Account автоматически. Routes в обеих оболочках через существующий first-party proxy, новый /account для управления/принятия. Нет второй object policy: существующий authorize_run_access уже проверяет active Account/tenant context.
