## Порядок на VM (шаги выдаются в чате по одному)

Из корня чистого committed checkout после `git pull --ff-only` до HEAD с этой
поставкой. Все каталоги evidence — вне checkout. Никаких секретов: шаги не
читают `.env`/DSN/MFA; PostgreSQL image читается как read-only discovery
живого контейнера, пароль тестовой БД генерируется внутри runner.

1. **Синхронизация и состояние**: `git pull --ff-only`; проверить HEAD;
   убедиться, что candidate running и volume/`manifest.json` соответствуют
   `922ff70c2381`; `export B='<точный путь bundle>'` (не подбирать через ls).
2. **Зависимости host**: venv `/opt/cisstat/venvs/pgv1314cert` с
   `scripts/pgv1314cert/requirements.txt` (+ scientific requirements для
   pytest), Pillow, `tesseract-ocr` rus+eng; `npm ci` при отсутствии/устаревшем
   `node_modules` (проверку делает сам `workspace_dependencies` — при
   несовпадении lock'а запуск `local` честно упадёт до вычислений).
3. **Local**: `verify.py local --out "$B/pgv1314-local"` — свежая сборка
   renderer, точный pytest-манифест (165 cases), print Jest 357 assertions без
   skips, 18 typography controls, CP1252 parity, actual routes/инвентарь,
   typecheck и обе production сборки; frozen fingerprints; source fence.
4. **Run (native, все 11 cases × каждая страница)**: read-only discovery
   PostgreSQL image живого `cisstat-stack` контейнера →
   `verify.py run --bundle "$B" --local "$B/pgv1314-local/summary.json"
   --postgres-image "$PG_IMAGE" --out "$B/pgv1314-native"`. Внутри:
   `validate_release` (все transport evidence + хеши bundle),
   `image_equivalence(e2da22c…)`, свежая `observe_live` всех трёх production
   образов/markers/socket, изолированный PostgreSQL/AuthSession/CSRF/AUTH-13
   managed worker на candidate, каждый PNG/ZIP/JSON/страница — CRC/geometry/
   300ppi/pixels/OCR/хеши, дополнительно pinned API-image/UDS client проверяет
   page-cap/oversized-atom (HTTP 413, `retryable=false`, header false),
   метрики cgroups, cleanup. Итог: `AWAITING_EVERY_PAGE_REVIEW` +
   `bindings.json` (local/report/release/fingerprints связаны).
5. **Review каждой страницы оператором**: скопировать `$B/pgv1314-native` с VM,
   открыть `review.html`, просмотреть **каждую** страницу каждого из 11 cases
   в полном размере (читаемость, кириллица, отсутствие crop/overlap, верные
   значения/reasons, повтор заголовков/folios); заполнить `review.json` из
   `review.template.json` (reviewer, aware `reviewed_at`), отмечать только
   реально проверенное; дефект — false + finding, finalize не запускать.
6. **Issue**: `verify.py issue --bundle "$B" --local "$B/pgv1314-local/summary.json"
   --report "$B/pgv1314-native/report.json" --review "$B/pgv1314-native/review.json"
   --out "$B/pgv1314-native/certificate.json"` — пере-валидация каждой
   страницы/OCR/хешей/semantic oracle/бюджетов/живых образов и запись
   immutable `pgv.tasks_certification/1`: `PGV-13=true`, `PGV-14=true`,
   `full_pgv_certified=false` (scope исключает PGV-15 UI, PGV-16, PGV-CERT).
7. **После акта**: сохранить evidence-каталоги/bundle/baseline/старые образы;
   остановить candidate можно только `down` **без** `-v` теми же `-p/-f`;
   evidence передаётся тимлиду/агенту для независимого итогового акта.

## Риски и границы

* Любой FAIL/отказ — стоп: сохранять `report.json`/логи/PNG как есть, новый
  запуск только в новый `--out`; не редактировать evidence/оракулы; не
  добивать PASS пересборкой fixture или повторным прогоном поверх.
* `run` использует ровно dedicated candidate release `922ff70c2381`; попытка
  нагрузки на production renderer отвергается самим harness'ом.
* Дифф `revision..HEAD` обязан оставаться host-only: любой коммит, меняющий
  product/эти инструменты между `local`, `run` и `issue`, ломает binding
  (`source_fingerprints`/`bindings.json`) и честно блокирует issue.
* Секреты с VM не извлекаются (AGENTS.md); отчёты harness не содержат
  Env/DSN/.env; каталоги evidence — 0700 вне checkout.
* HTTP-поверхность, DTO, BFF, OpenAPI, IPC, SQL, DDL, роуты — без изменений
  этой поставкой; карта 285/289/669 сохраняется (гейт check_routes в поставке).
* Rollback не затрагивается: baseline `cb1635c6/0c74b32b/55278b45` и прежние
  volumes сохраняются; `operation.json` релиза не редактируется.
* После успешного `issue` итоговый сводный акт PGV-13 пишет отдельной
  поставкой на основе certificate.json и evidence — этим runbook'ом он не
  подменяется.
