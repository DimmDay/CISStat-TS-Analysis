# Почему после анализа демо не появились документы

Проверено на `f1d6151`, 26 октября 2026 года. Полный акт — `certification.md` рядом с этим файлом.

**Ваше наблюдение воспроизводится.** Это не признак того, что вы неправильно подтвердили структуру или обработали пропуски/выбросы.

В текущем продукте три отдельных уровня:

1. Данные, паспорт свойств и результаты этапов в исследовательской сессии.
2. Устойчивые научные артефакты, из которых собираются замороженные документы.
3. Реестр документов и их MD/HTML/JSON/PDF-представления.

Первый уровень в сценарии работает. Связь первого со вторым не подключена, а третий пополняется явной командой создания. Автоматического появления готового документа после каждой остановки сейчас нет. Само открытие раздела документы не создаёт, что правильно для операции просмотра.

Но и явное создание первого документа через UI недоступно: успешный пустой список переключает интерфейс в `empty`, тогда как кнопка «Создать черновик» разрешена только в `ready`. Дополнительно общий бейдж «Документы» открывает страницу без `run` и не восстанавливает активное исследование. Ссылка из «Прогресса» передаёт run, но не устраняет тупик первого документа.

В отдельном опыте выбраны медианное заполнение (`median_mode`) и ограничение IQR (`cap`). Получено 0 пропусков и 0 выбросов, 150 строк сохранены. Ваши конкретные методы не известны — это воспроизведённый вариант, а не копия вашей сессии.

После структуры, паспорта, валидации и обеих коррекций: **0 документов, 0 устойчивых артефактов**. Затем явными API-запросами созданы три документа, собраны их MD/HTML/JSON/PDF.

Содержимое приложенных образцов:

- **D02, «Паспорт источника»** — сведения о загрузке и сообщение, что паспорт не продвинут в устойчивый слой. Это не полная выгрузка рассчитанного паспорта свойств.

- **D04, «Рецепт преобразований»** — факты применения коррекций; полноценного параметризованного рецепта со стратегиями/числами и данными ещё нет.

Все три имеют `limited / missing_data_artifact`. Продукт одновременно выставляет им `complete`; в акте это выделено как недостаточная семантика полноты. Сохранённые PDF не редактировались ради улучшения этого результата. Вдобавок исторические события до коррекций ошибочно помечены актуальными к последнему контексту.

## Проверенный обход UI-тупика

Для собственной текущей сессии есть явный API:

```text
GET  /v1/progress/trace
POST /v1/documentation/runs/{run_id}/documents
body: {"kind":"D02","refresh":true}
```

Повторить POST для D03 и D04, затем открыть `/documentation?run={run_id}`. Используется та же cookie-сессия; UUID/ID документа сами по себе не дают доступ. В production standalone API обычно доступен через first-party `/api` proxy.

Пример для консоли **своей открытой страницы standalone с настроенным `/api` proxy**; код создаёт три черновика, не выполняет новые преобразования данных:

```javascript
const api = "/api";
const traceResponse = await fetch(`${api}/v1/progress/trace`, {
  credentials: "include"
});
if (!traceResponse.ok) throw new Error(`Trace HTTP ${traceResponse.status}`);
const trace = await traceResponse.json();
if (!trace.run_id) throw new Error("В текущей сессии нет исследования");
for (const kind of ["D02", "D03", "D04"]) {
  const response = await fetch(
    `${api}/v1/documentation/runs/${encodeURIComponent(trace.run_id)}/documents`,
    {
      method: "POST",
      credentials: "include",
      headers: {"Content-Type": "application/json"},
      body: JSON.stringify({kind, refresh: true})
    }
  );
  if (!response.ok) throw new Error(`${kind}: HTTP ${response.status}`);
}
location.assign(`/documentation?run=${encodeURIComponent(trace.run_id)}`);
```

Этот обход оставляет ограничения содержимого и воспроизводимости, перечисленные выше. Для локального dev/другого прокси нужно подставить его реальную API-базу. В вашей реальной сессии этот код сертификатором не запускался.
