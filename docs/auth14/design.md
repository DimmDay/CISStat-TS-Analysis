# AUTH-14 — план и границы

База a16b31bd0c3d49586de24d3556a39e43b9cc3321, 08.11.2026, Москва. Прочитаны AGENTS, spec_auth/spec_auth_architecture, CU §4/13 billing, AUTH-01…13 записи журналов11/12 и ядра PELT/tuning/worker/ledger. Отдельное detached worktree; commit/push/VM не выполняются.

Профиль CU получается только реальным benchmark конкретного host/software/resource envelope. Сохраняются raw wall/CPU/RSS, seed, параметры, actual PELT passes/jump/grid и selected trials/folds. Коэффициент/показатель оцениваются по тренировочным точкам, проверяются на отдельном seed. Синтетический профиль допускается только в unit/SQL-тестах и не выдаётся за production calibration.

Тариф: 1 CU = 1e6 micro-CU. Один attempted fold/PELT fit — billable unit; до его начала записывается supervised progress. Стоимость unit — детерминированный Decimal base × normalized volume^exponent, округлённый вверх в integer micro-CU; сумма — integer unit price × actual attempted units. CPU/wall/RSS — доказательство calibration и runtime control, не изменяющийся от нагрузки денежный счётчик. Prepaid estimate включает фактически выбранные trials×folds или PELT worst-case passes. Meter запрещает дополнительный fit сверх резерва до его старта. Timeout/kill не дают бесплатного повторного fit: подтверждённый supervisor progress учитывает начатые units; unknown outcome удерживает hold.

Исходные алгоритмы/параметры науки сохраняются: переиспользуются MAX_PELT_GRID_POINTS/jump и все tuning engines/EDA folds. Изолированный runtime ограничивает wall/memory и current authority, а профиль только сужает текущие server ceilings. Непокрытые модель/rows/columns/folds/trials/seasonality, изменённые kernel/dependency/hardware fingerprints и повреждённый профиль дают явный отказ в calibrated режиме, без нулевой цены/fallback. Без включённого профиля сохраняется AUTH-13 unpriced mode, с конечными server bounds. Локальный profile — воспроизводимый reference, не измерение VM. Коммерческий запуск/credit/wallet не включаются этой задачей.

Интеграция: существующие stepped aliases получают сохранённую immutable quote version; sync tuning и PELT проходят тот же runtime/settle/fencing, stateless scoped API не подменяется surrogate run. Session result CAS и settle атомарны; direct response публикуется только после settle. Global running+uncertain capacity ceiling сериализуется в PostgreSQL для всех Accounts, отдельно от per-account quota. Старые admitted jobs не переоцениваются по новому profile.

Повторы: обязательный current-authority cache для PELT GET; явный Idempotency-Key для POST tuning. Сохранённый итоговый TuneResponse (после promotion), а не промежуточная trial projection, записывается в private content-addressed store, ссылка/hash подписываются в stop proof. DB publication/settle остаются одним commit. Replay не делает повторную запись scientific artifacts и не переносит raw результаты в ledger. Missing cache даёт503 без нового списания. Idempotency-Key проходит через существующий BFF; HTTP methods/paths/DTO не добавлены.

Отдельный supervisor thread контролирует физический deadline и aggregate Linux process-group RSS независимо от DB pulse. RED-тест с блокированным pulse подтвердил выход за исходный deadline; GREEN подтверждает отсутствие выполнения за границей. Sampling≤50мс + OS scheduling и CPU/data rlimits, положительная остановка native descendants перед receipt; время SQL-ответа не выдаётся за физическое время fit. Ограничение количества fits — точное до их начала; научные failures входят в фактические attempted units. Sync whole-plan и async per-trial boundaries различены отдельным тестом; генерируемые features входят в normalized volume.
