FP — отпечаток тела батча (свои payload, кириллица)

  [PASS] FP2 другой payload → другой отпечаток
  [PASS] FP3 другой run_id → другой отпечаток
  [PASS] FP4 контекст входит в материал отпечатка
  [PASS] FP5 префикс sha256: и hex-длина 64

  [PASS] ATOM1 отказ на последнем событии поднят
  [PASS] ATOM2 после отказа ноль событий
  [PASS] ATOM3 метаданные прежние после отказа
  [PASS] ATOM4 receipt отказавшего батча НЕ зарегистрирован
  [PASS] ATOM5 retry после отказа принят
  [PASS] ATOM6 retry ровно одна копия каждого события
  [PASS] ATOM7 отказ на первом: метаданные байт-в-байт прежние
SEQ-M — sequence per run: чередование, независимость запусков
  [PASS] SEQ1 непрерывный префикс 1..5 при чередовании
  [PASS] SEQ2 sequence независима per run (второй запуск с 1)
  [PASS] SEQ3 конкурентные батчи: непрерывный 1..40 без дублей/дыр
RCP-M — receipt: безключевой, два ключа, retry после дописанных
  [PASS] RCP1 безключевой батч возвращает receipt с пустым ключом
  [PASS] RCP2 безключевой: get_commit_receipt вернёт None
  [PASS] RCP3 два РАЗНЫХ ключа на одно тело — оба приняты независимо
  [PASS] RCP4 retry старого ключа возвращает СТАРЫЙ watermark и ТЕ ЖЕ accepted-ids
  [PASS] RCP5 retry старого ключа НЕ дописывает события
  [PASS] RCP6 форма receipt: run/context/ids/watermark/created_at
  [PASS] RCP7 get_commit_receipt возвращает сохранённый
  [PASS] RCP8 accepted-ids — принятые (дедуплицированные не входят)
  [PASS] RCP9 прочитанный receipt частичного батча: accepted = принятые
CAS-M — expected context: привязка/совпадение/отключение/stale
  [PASS] M1 stored NULL + expected → первичная привязка принята
  [PASS] M2 совпадающий контекст принимается
  [PASS] M3 stale-контекст отклонён (CommitConflictError)
  [PASS] M4 после CAS-отказа ноль новых событий от производителя
  [PASS] M5 ключ пережил CAS-отказ: retry с исправленным контекстом принят
  [PASS] M6 expected=None отключает CAS (advisory)
  [PASS] M7 предусловие: run существует с контекстом NULL
  [PASS] M8 stored NULL + существующий run → первичная привязка, не конфликт
COA-M — COALESCE-слияние аддитивных полей run
  [PASS] M1 None-батч не стирает context/revision/digest
  [PASS] M1b receipt None-батча несёт слитый контекст
  [PASS] M2 digest обновлён, контекст сохранён
  [PASS] M3 target_column записан напрямую
  [PASS] M4 target_column=None сбрасывает цель (не COALESCE)
