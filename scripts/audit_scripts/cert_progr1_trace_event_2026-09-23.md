- **аддитивность**: `timestamp` сохраняется legacy-алиасом — pydantic-схема ответа `ForecastTraceEventSchema` (apps/api/schemas.py::3518) объявляет его обязательным, фронтенд-интерфейс `ForecastTraceEvent` (packages/ui/lib/forecasting.ts::30) его читает;

- **реестр** `STAGE_EVENT_TYPES` по таблице §4.1, run-level типы (`run_paused/run_resumed/checkpoint_saved`) валидны на любой стадии;
- **fail-closed**: неизвестная (stage, event_type)-пара не попадает в трассу молча.

Критерии приёмки плана: (1) RED→GREEN новые тесты канона; (2) ноль правок forecasting_session.py; (3) полный suite tests/api без новых падений.

## 7. Находки и замечания

- **R1 (формулировка журнала, не блокирует).** Копия payload в `to_dict()` и в `normalize_trace_event_dict()` поверхностная: верхний уровень изолирован, вложенные dict/list разделяются с событием / stored-входом (оракулы C5b/D4b). Спецификация глубину не требует; реальные payload всех 4 call-site — плоские факты. Уточнить формулировку в worklog7 («глубокая копия» → «копия верхнего уровня») либо сделать копию глубокой в PROGR-3, когда появятся вложенные факты.
- **R2 (граничный случай, не блокирует).** Маркер legacy-популяции — «timestamp есть, ts нет» — принудительно ставит стадию forecasting, игнорируя явную стадию в словаре (оракул D6b). Сегодняшняя legacy-популяция вся прогнозная — последствий нет; при появлении частично-канонных stored-событий с алиасом возможна неверная атрибуция стадии. Зафиксировать решение в PROGR-3 (граница чтения трассы).
- **R3 (дизайн-решение, зафиксировать).** `normalize_trace_event_dict`/`from_dict` валидируют стадию, но НЕ event_type по реестру (оракул D7b) — опечатка типа проходит границу чтения. Fail-closed живёт только в фабрике. Решение защитимое (корпус должен переживать эволюцию реестра), но оно должно быть осознанным: зафиксировать в тексте спеки/докстринге к PROGR-3.
- **R4 (недостижимые дефолты, гигиена).** Дефолты полей датакласса (ts/stage/node_id/actor/payload/event_id/run_id) не достижимы ни через одну публичную точку: фабрика и from_dict передают все 8 полей явно; прямых конструкций `TraceEvent(...)` вне модуля нет (grep). Мутант-зонд MUT-19 (порча всех дефолтов) выживает — тестов на прямое конструирование нет. Сегодня это безвредно; в PROGR-3 появятся первые прямые потребители — тогда дефолты станут «живыми» и потребуют собственного теста (либо явного запрета прямого конструирования).
- **R5 (средовые требования, процесс).** Прогон tests/api требует полной установки `apps/api/requirements.txt` (включая prophet/statsforecast/arch/нейро-опциональность) И statsmodels>=0.15.0: при 0.14.5 все 16 прогнозных E2E падают с честным 422-сообщением о симуляции. Предложить: зафиксировать в README тестового контура чек-лист версий (prophet 1.4.0, statsforecast 2.1.1, xgboost 2.1.3, lightgbm 4.5.0, catboost 1.2.8, statsmodels>=0.15.0, arch>=7.0.0).
