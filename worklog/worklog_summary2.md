## 4. Новый этап «Прогнозирование» — полный вертикальный срез (Task FORECAST-1)

Реализован по `spec_forecasting2.md` v3 с честными уточнениями под фактический код (Model Execution Contract v2, production-адаптеры деревьев/нейросетей).

### Ключевые решения

1. **Исполнение через MODEL_EXECUTION_REGISTRY** (не PRODUCTION_PREDICTORS) — та же сертифицированная точка исполнения, что и бэктест.

2. **Хранение артефактов** — `modeling_artifacts["forecasts"]` (не `modeling_pipeline["forecasts"]`, который есть `dict[str, StageStatus]`).

3. **4 метода доверительных интервалов**:
   - `analytic` — ARIMA/Auto-ARIMA (get_forecast().summary_frame(alpha)), Theta (prediction_intervals)
   - `parametric_simulation` — ETS/ETS Damped (simulate + rng)
   - `native_adapter` — Prophet/TBATS (80%), tree_ml (90%), LSTM/N-BEATS/N-HiTS/TFT (alpha-ручка)
   - `empirical_oof_quantile` — baseline-модели (квантиль OOF-остатков своего шага горизонта)
   - var/vecm/garch/egarch/deepar — честный 422 (objective-изоляция cohort'ов)

4. **Паритет-гейт** для analytic/simulation: интервальный фит строится зеркалом сертифицированного адаптера, расхождение с точкой реестра (rtol 1e-6) → ForecastingError.

5. **Freshness-гейты**: fingerprint ряда обязан совпадать с card.data_summary.fingerprint (409 «Model Card устарела»).

6. **Экспорт**: CSV/JSON (backend), PNG (клиентская SVG→canvas сериализация). PDF сознательно НЕ реализован (кириллические шрифты jsPDF требуют встраивания ~200+ КБ).

### Frontend

TsAnalysisForecasting.tsx — 3-колоночный лейаут:
- Левый: шапка + справка + шаги этапа + hand-off карты
- Центр: описание/справка, ForecastChart (факт + пунктирный прогноз + лента интервала Area + красные аномалии), ForecastAccuracyPanel, предупреждения, веер
- Правый: селектор карт, горизонт, alpha {0.01, 0.05, 0.10}, кнопка прогноза, история с чекбоксами сравнения (до 3), ForecastExportMenu

### Сертификация

**ПРОЙДЕНА С ЗАМЕЧАНИЯМИ**: 25 оракулов на независимых DGP аудитора, 15/15 мутаций KILLED. Один обязательный к закрытию дефект: F-1 — путь симуляции ETS использует API statsmodels>=0.15, а requirements декларируют пол >=0.14.0. Закрыт в Task FORECAST-1a.

## 9. Калибровка soft_min_observations (Task 145)

**Метод**: парный end-anchored sliding на каноническом движке. Для каждого n строится план с ФИКСИРОВАННЫМИ тестовыми окнами (последние K=4 окна ряда), train = n наблюдений непосредственно перед окном.
