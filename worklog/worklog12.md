### Диагноз (по вложению и коду):
Fixture-форма p02-reused: checkpoint.flags={created:false, reused:true, unchanged:false}, previous_ref=null, reused_ref = ref exit-снимка (последняя запись пути). Резолвер apps/api/passport_comparison.py (строка 356 базы) выводил confirmation.unchanged=true по деривации «reused + отсутствующий previous», игнорируя явный false; печать P02 «Состояние совпало с предыдущим снимком» противоречила чекпоинту. Причина контрактная: продюсер (passport_checkpoints.py) писал flags.unchanged=False ВСЕГДА («не заявляется»), резолвер компенсировал деривацией из session-конвенции (freeze не пишет самоссылку) -- явный false и «флаг не заявлен» были неразличимы, а отсутствие previous трактовалось как доказательство. Попутно найден дефект дедупликации: unchanged-дроп терял осмысленную пару возврата (reuse более старого снимка при отсутствующем previous), и ложная метка печати previous_ref: «нет (unchanged)».

### Дизайн: docs/pgv13_unchanged_semantics.md (§3):
1. Продюсер заявляет доказуемое: modeling_entry unchanged = not created && previous_snapshot_id == snapshot_id -- ТОТ ЖЕ доказуемый критерий, что unchanged_from_previous session-контура; panel_entry -- False (previous==self -- конвенция confirm; 409-гейты гарантируют изменённый fingerprint нового подтверждения). Валидатор AC11 (unchanged⊆reused, not with created) не ослаблялся.
2. Резолвер: confirmation.unchanged -- tri-state (true/false/null) + новое аддитивное поле unchanged_basis; приоритет «доказательство refs > явный флаг продюсера > неизвестность»: previous есть и ref равен -- previous_ref_identity (true); previous есть и ref отличен -- previous_ref_differs (false); previous отсутствует + явный true -- producer_flag; previous отсутствует + ЯВНЫЙ false -- producer_flag_false (ЯДРО ФИКСА: false не превращается в true); previous отсутствует + флага нет -- unknown_no_evidence (null, неизвестность -- отдельное состояние).
3. Дедупликация -- ОТДЕЛЬНОЕ решение: этап подтверждения исключается из пути ТОЛЬКО как алиас НЕПОСРЕДСТВЕННО предыдущего элемента пути (иначе была бы нулевая самопара, §9/AC11); алиас более раннего снимка ОСТАЁТСЯ (пара возврата сохраняется); fixture-путь start/validation/exit сохранён (паритет frozen payload).
4. Печать printComparison.tsx: unchanged: boolean | null + unchanged_basis; честные фразы трёх состояний (false-ветка различает reused/created; null -- «неизвестно»); метка previous_ref «нет (unchanged)» заменена на «нет в записи чекпоинта».
5. Fixture/checkpoint/payload/PNG/report/review -- только вход, байты не переписывались.
